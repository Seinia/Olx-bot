# OLX Monitor

Телеграм-бот, который следит за объявлениями на [olx.ua](https://www.olx.ua) и присылает
новые, как только они появляются. Задача — увидеть выгодный лот раньше остальных, поэтому
всё построено вокруг скорости реакции: медианная задержка от публикации до уведомления
около 15 секунд.

Инструмент личный: один владелец, 1–5 отслеживаемых запросов, бытовой объём обращений
к площадке.

## Что умеет

- **Два способа задать запрос.** Поисковая фраза, как на OLX, — или раздел целиком,
  без фразы: например, «все легковые автомобили» без марки и модели. Во втором
  случае мастер даёт пролистать дерево разделов OLX и остановиться на любом уровне
  кнопкой «Весь этот раздел целиком».
- **Мониторинг с фильтрами** — цена, город или область целиком, раздел, состояние,
  тип продавца. Все фильтры серверные, плюс стоп-слова на своей стороне: отсекают
  «на запчастини», «подобово», «з iCloud» по заголовку.
- **Город или вся область.** Один конкретный город — или сразу вся область
  («Львівська», «Одеська» и т.д.), без выбора между райцентрами вручную.
- **Два режима опроса.** `fast` — раз в 25 секунд, первая страница выдачи.
  `full` — раз в 10 минут с полным обходом пагинации.
- **Три режима уведомлений.** Только новые; новые плюс изменение цены; новые плюс
  переподнятые (вручную или платным автоподъёмом) плюс изменение цены — когда
  продавец поднял объявление, это часто означает, что он готов торговаться.
- **Настройка целиком через Telegram** — мастер с инлайн-кнопками, разделы и города
  подставляются из справочников OLX.
- **История цен.** Каждое изменение цены сохраняется; отчётов пока нет, данные копятся.
- **Выгрузка** находок в CSV или JSON.

## Мастер /add

Первый вопрос — «по фразе» или «по разделу, без фразы»:

- **По фразе** — как раньше: вводите текст, мастер сам подскажет, в какие разделы
  он попал, если их несколько.
- **По разделу** — дерево категорий OLX с кнопками. На любом уровне можно нажать
  «Весь этот раздел целиком» и не спускаться до конкретной марки/модели — тогда
  отслеживаются все объявления раздела и всех его подразделов сразу (сравнение идёт
  по поддереву `category_id`, а не по точному совпадению: у родительских разделов
  вроде «Легкові автомобілі» своих объявлений нет, они лежат в марках-подкатегориях).

Дальше на шаге города — обычный выбор одного города, свой вариант вручную, «вся
Украина» — или «вся область»: вводите название («Львівська», «Одеська») и запрос
будет отслеживать объявления по всей области, а не по одному городу.

**Важно про `region_id`.** У OLX нет публичной документации на этот параметр
поиска. Он выведен по аналогии с `city_id` из структуры ответа API (каждое
объявление приходит с полным объектом `location.region`), но не проверен вживую —
в этой сборке не было доступа к olx.ua для реального прогона. Если после
обновления область не фильтрует объявления так, как ожидается, включите живые
тесты (`OLX_LIVE_TESTS=1 pytest tests/test_api.py -k region -q`) и сверьтесь
с реальным ответом API; при необходимости замените параметр в `api.py`
(`build_search_url`) на тот, что реально фильтрует по региону.

## Как это работает

```
Telegram  ──/add──▶  bot.py  ──▶  storage.py (SQLite)
                                      ▲
                                      │
  olx.ua  ◀── transport.py ◀── api.py ─┴─▶ parse.py ──▶ monitor.py ──▶ notify.py ──▶ Telegram
```

Три вещи, которые определили архитектуру:

**Доступ к API идёт через `curl_cffi` с подменой TLS-отпечатка.** Это не оптимизация,
а условие работы: голый HTTP-клиент получает 403 от CloudFront на любой запрос ещё до
всякой бизнес-логики. Проверено — 5 попыток из 5.

**Выдаче OLX нельзя верить.** Параметр `private_business` принимается сервером и молча
не фильтрует. Когда результаты по фильтрам заканчиваются, API не отдаёт пустую страницу,
а добивает её посторонними объявлениями — по запросу «квартира за 9000–15000 грн»
приезжали входные двери за 180 грн. Поэтому каждое объявление проверяется против фильтров
повторно, уже на нашей стороне.

**Порядок выдачи нестабилен.** Ответы приходят с разных узлов, и одно и то же объявление
перебрасывается между позициями и даже между соседними страницами. Детектор новизны
сравнивает множества идентификаторов и никогда — порядок.


## Установка

Нужен Python 3.11+.

```bash
git clone https://github.com/Magerko/olx-radar.git
cd olx-radar
python -m venv .venv
.venv/bin/pip install -e .          # Windows: .venv\Scripts\pip
```

Создайте `.env` в корне:

```ini
TELEGRAM_BOT_TOKEN=токен от @BotFather
TELEGRAM_OWNER_ID=ваш числовой id, узнать у @userinfobot

DB_PATH=./data/olx.db
POLL_INTERVAL_FAST=25
POLL_INTERVAL_FULL=600
FULL_MAX_PAGES=10
SILENCE_ALERT_HOURS=12

PROXY_ENABLED=false
PROXY_LIST_FILE=./proxies.txt
```

Запуск:

```bash
python -m olx
```

Откройте бота в Telegram, нажмите Start и отправьте `/add`.

## Команды

| Команда | Что делает |
|---|---|
| `/add` | мастер создания запроса |
| `/list` | все отслеживаемые запросы |
| `/edit` | цена, стоп-слова, режимы, пауза |
| `/del` | удалить запрос |
| `/export` | выгрузка в CSV или JSON |
| `/status` | состояние монитора |
| `/pause`, `/resume` | приостановить и возобновить опрос |
| `/help` | справка |

Бот отвечает только владельцу — сообщения с любого другого аккаунта отбрасываются молча.

## Справочники

Названия разделов и городов OLX через API не отдаёт, поэтому они собираются скриптами
и лежат в репозитории:

```bash
python scripts/refresh_categories.py   # дерево разделов из вёрстки главной страницы
python scripts/refresh_cities.py       # города из выдачи по широким запросам
```

Запускать вручную, когда OLX перекроит структуру разделов.

## Разработка

```bash
.venv/bin/pip install -e ".[dev]"
pytest tests/ -q                       # 204 теста, ~10 секунд
ruff check src/ tests/ scripts/
```

Тесты, которые ходят в сеть или шлют настоящие сообщения в Telegram, по умолчанию
пропускаются. Включаются осознанно:

```bash
OLX_LIVE_TESTS=1 pytest tests/ -q
```

## Развёртывание

Systemd-юнит и инструкция — в [`deploy/`](deploy/). Кратко: venv на сервере,
`.env` рядом, `systemctl enable --now olx-monitor`.

Один процесс на один токен бота: Telegram отдаёт обновления только одному получателю,
и второй запущенный экземпляр начнёт перехватывать команды через раз.

## Ограничения

- Только `olx.ua`, только один владелец, без веб-интерфейса.
- Проект держится на **недокументированном внутреннем API OLX**. Он не версионируется
  и может измениться без предупреждения. Поэтому разбор ответа падает громко, а не
  возвращает пустой список: молчащий монитор неотличим от монитора, для которого
  просто нет новых объявлений.
- `robots.txt` OLX закрывает search-пути, а правила сервиса запрещают агрегацию данных
  **с целью передачи третьим лицам**. Инструмент читает публичную выдачу в бытовом
  объёме для личной покупки и никуда её не перепубликует. Если вы собираетесь
  использовать это иначе — правовая ситуация меняется.
